## 1. Introduction & Overview

`03-ai-groove-recorder` adds the second core differentiator over *Real Drum*:
1. **AI Text-to-Groove Generator:** Type any musical prompt (e.g., *"94 BPM J Dilla neo-soul boom bap with swung hi-hats and ghost snares"* or *"165 BPM drum and bass amen break"*) to generate a validated, playable `GroovePattern` (via Gemini `gemini-2.5-flash` structured JSON when online with an API key, or deterministically via `:core`'s `ProceduralGrooveGenerator` when offline).
2. **Multi-Take Session Recorder & Quantizer:** Record live finger-drumming takes on the Drum Stage, apply optional `1/16`-note grid quantization, replay loops with ghost-pad animations, and persist custom grooves/takes locally.

### Assumptions (Flagged for Review)

- **A1 (Offline Resilience):** AI Text-to-Groove MUST never fail or block the user if no Gemini API key is configured or the device is offline; it automatically falls back to `ProceduralGrooveGenerator` in `:core` and badges the source (`Cloud AI` vs. `Smart Studio Engine`). **Confirmed.**
- **A2 (Event-Based Recording):** Session recording captures `RecordedHitEvent(padId, offsetMs, velocity)` rather than raw microphone audio, requiring zero `RECORD_AUDIO` permissions. **Confirmed.**

### Domain Glossary

- **`AiGrooveRequest`:** User text prompt (`3..200` chars) + optional target kit override.
- **`ProceduralGrooveGenerator`:** Pure-Kotlin rule/grammar beat generator in `:core` that extracts BPM (`40..240`), swing (`0..75%`), and genre archetypes (*boom bap, trap, rock, metal, funk, house, dnb, jazz, punk, lofi*) from any text prompt.
- **`LoopQuantizer`:** Pure-Kotlin transformer in `:core` that snaps recorded `offsetMs` hit timestamps to the nearest `1/16` (or swung `1/16`) step grid.

## 2. Requirements & EARS Acceptance Criteria

### Requirement 1: AI Text-to-Groove Generation (Gemini + Offline Procedural Fallback)
**User Story:** As a drummer or beatmaker, I want to type a musical vibe or tempo prompt and immediately get a playable drum groove, so that I can practice or jam to any style on demand.

#### Acceptance Criteria
1. **1.1:** WHEN the user submits a non-empty prompt (`3..200` characters) in the AI Groove modal, THE `AiGrooveGeneratorPort` SHALL return a validated `GroovePattern` with clamped `bpm` (`40..240`), `swingPercent` (`0..75`), and valid `DrumPadId` steps within `[0..stepsPerBar * bars - 1]`.
2. **1.2:** WHERE a Gemini API key is configured and network is reachable, THE `GeminiAiGrooveAdapter` in `:platform` SHALL request structured JSON from Gemini and validate it via `GrooveJsonCodec`; IF the network/API is unavailable or unconfigured, THEN THE adapter SHALL seamlessly return a pattern generated by `:core`'s `ProceduralGrooveGenerator`.
3. **1.3:** IF the user submits a blank or `< 3` character prompt, THEN THE `AiGrooveRecorderViewModel` SHALL reject the submission and display an inline validation message without calling the generator.

---

### Requirement 2: Live Session Loop Recording, `1/16` Quantization & Local Persistence
**User Story:** As a finger-drummer, I want to record my live performance, optionally quantize my timing to a 16th-note grid, and save/replay my loops, so that I can capture beat ideas anywhere.

#### Acceptance Criteria
1. **2.1:** WHILE recording mode (`REC`) is active on the Drum Stage, THE `SessionRecorderEngine` in `:core` SHALL capture every triggered `DrumPadId` with its relative `offsetMs` from recording start and `velocity`.
2. **2.2:** WHEN the user toggles **Quantize 1/16** on a recorded take, THE `LoopQuantizer` in `:core` SHALL snap each hit's `offsetMs` to the nearest 16th-note grid interval for the current BPM and swing while preserving the original unquantized take for non-destructive undo.
3. **2.3:** WHEN the user saves a generated groove or recorded loop, THE `FileGrooveRepositoryAdapter` in `:platform` SHALL persist the JSON file in app-scoped storage (`filesDir/grooves/`) and reload saved items across app restarts.
